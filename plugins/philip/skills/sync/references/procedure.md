> **선택 팩(오프라인 전용)**: git 원격을 못 쓰는 프로젝트(인터넷 없음·폐쇄망·현장 배포)만 채택. git 이 있으면 이 커맨드 대신 커밋/푸시로 대체한다.

공유 매체 **SYNC_ROOT**(프로젝트 `.claude/psp.config.json`의 `"sync_root"` 값 — 예: USB·NAS·공유 드라이브 경로. 미설정이면 사용자에게 물어 설정 후 진행)로 머신들을 동기화하라. 이 매체가 **유일한 연결망**이므로 여기서 상태가 갈리면 프로젝트가 갈라진다. **SSOT = `SYNC_ROOT/docs/SYNC_PROTOCOL.md`**(이 커맨드는 그 실행 절차 요약 — 충돌·세부는 그 문서가 정답). $ARGUMENTS = `push`(로컬→공유, 기본) 또는 `pull`.

## 대원칙
동기화 = 파일 복사 아님 = **변경 후에도 모든 머신이 모순 없이 돌아가게.** 개념/방식을 바꿨으면 파급 grep → 고아 처리(고치거나 삭제) → config 머지 → 파급 알림까지. 완료 판정 = 상대 머신 기준으로도 import·기동·의미충돌 0.

## 0단계 (무조건 먼저 — 추측 금지)
- **공유 로그부터 읽는다**: SYNC_ROOT 의 변경기록(`log/` 최신 md) — 상대가 뭘 올렸는지·방향·부류별 지침. mtime·폴더 겉모양으로 판단 금지.
- 차이 확인 = **전수 해시**(md5 등). sync 전·후 각 1회, 차이 0까지. 보고전용, 복사는 손으로.

## 부류별 처리
- **순수 로직 코드**(코어·서비스) → 통째 교체(해시 동일 검증).
- **설정 파일**(config) → **머지만, 통째복사 금지**(머신값·그 머신 로컬추가 보존).
- **런처/스크립트**(.bat/.sh/.ps1) → 머신·환경별 적응(env 명 다름. bat=ASCII only).
- **머신 로컬 제외** → 자동생성물·시크릿·빌드산출물(`node_modules`·빌드캐시·`*.engine`·로컬 시크릿·머신별 설정값 등).
- **로그 = 1급 대상, 전 위치 합집합** → 각 머신·공유매체의 변경기록을 **파일수 일치까지** 서로 없는 것 전부 복사(덮어쓰기 X, 동명 다른내용=충돌보고). 한 곳에만 두면 상대 머신 맥락 상실.
- **문서**(README·상태·이슈·요구사항·매뉴얼) → 양쪽 고쳤으면 둘 다 반영.

## push (로컬→공유) — 이 순서 한 번에
1. 0단계(공유 로그 읽기) → 파급 grep(바꾼 키·함수 쓰는 곳, 상대 추가분 포함) → 고아 이번에 처리.
2. 바뀐 코드 공유매체 반영(부류별) + 해시 공유==로컬 검증 + 빌드/컴파일 확인 + config 실로드.
3. **로그 전 위치 합집합** + 이번 sync 로그 자체도 남김(머신명·수치·**부류별 pull 지침·상대 할 일**, 시각은 실측).
4. 이슈·상태 문서 갱신(의미충돌/해결 항목·상대 할 일·날짜·완료항목).
5. 머신로컬 안 올림 · 개발중 아니면 서버·백그라운드 종료.

## pull (공유→로컬)
1. 0단계 로그 읽기 → 백업 후 적용.
2. 순수로직 통째 / config 머지 / 런처 env적응 / 머신로컬 제외 / **로그 전 위치 합집합**.
3. 빌드/컴파일 + config 실로드 + 전수 해시 재비교(잔여차 = config머지·머신·자동생성만).
4. **★로컬 상태문서(todo/이슈표) 갱신** — 코드는 넘어와도 진행표는 공유매체 안 넘음. landed 된 상대 fix 를 내 상태표에 반영(검증출처="상대머신 실측").
5. **★로컬 메모리 갱신도 sync 의 일부** — pull 로 landed 된 **확정 결정·기준값 변경·실측 팩트**(예: e2e 기준값·판정 기준·프로토콜 결정)를 해당 메모리 본문에 반영. 안 하면 상시체크 메모리가 낡아 다음 세션이 옛 기준으로 판정한다(실사고: 기준값 110→109±2 변경이 pull 4회 동안 메모리 미반영). ★반영 규격 = **그 파일의 기존 규격 그대로(일자별 항목 등) — 여러 날치를 한 덩어리로 뭉치는 압축 블록 금지**(사용자 교정). 진행 상태 서술은 여전히 금지(todo 가 SSOT) — 결정·기준·팩트만.

프로세스: sync 는 기계적 — 방향 받으면 "할지 말지" 묻지 말고 실행. 만든 걸 내 판단으로 빼지 마라(뺄지는 사용자). 의미충돌은 이슈 등록하고 sync 는 안 막는다.
