description: 실측 검증 — 추측·문서·grep을 넘어 실행으로 반증. 인자 = 검증 대상
---
$ARGUMENTS 를 실측으로 검증하라. 단계별 상승 — 아래로 갈수록 강하며, **가능한 가장 강한 단계까지** 간다:

1. **정독**: 관련 파일을 처음부터 끝까지(부분 읽기로 단정 금지).
2. **grep 교차**: 주장에 등장하는 식별자(신호명·키·함수·설정)가 실제 코드에 존재하고 **발행자/호출자가 있는지** 전수 확인 — "선언됨"과 "배선됨"을 구분(문서·툴팁은 증거가 아니다).
3. **실행 반증**: 핵심 전제를 **cheap runtime probe**로 실제 실행해 반증 시도(유닛 테스트·스크립트·MCP execute·REPL — 환경에 있는 가장 싼 수단). 특히 보안·결정성·성능·"이 API가 이렇게 동작한다" 류 전제는 grep으로 끝내지 말 것.
4. **관찰 종료 조건**: 동작 검증은 시작→진행→종료까지 끝까지 본다(한 프레임·정지 화면·측정값 하나로 단정 금지). 사용자가 본 증상이 내 측정과 모순되면 **증상이 우선** — 내 데이터를 의심한다.

**보고 양식**: 전제 → 검증 수단(단계) → 관찰 결과 → 판정(성립/반증/실측 불가+이유). 실측 불가면 "검증 대기"로 명시하고 어디에 게이트로 박았는지 적는다 — 불가를 통과로 바꾸지 말 것.
