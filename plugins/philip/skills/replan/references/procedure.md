계획 변경을 처리하라: $ARGUMENTS

절차 (목표 5분, 산문 재작성 금지):
1. **어디가 바뀌나 판정** — 순서만? 범위(추가/삭제)? 마일스톤 단위?
2. **순서 변경** = 현행 `index.md` phase 표에서 **행 이동**만(번호는 불변 ID — 재번호 금지). 마일스톤 순서면 `roadmap.md` 표 행 이동.
3. **추가** = 새 phase ID(끝번호 또는 P4b식)로 행 1줄 삽입(제목·목표·acceptance 한 줄). 세부 작업 항목은 그 phase 시작할 때(지금 채우지 말 것 — 집만 짓기). 먼 마일스톤이면 roadmap 행 1줄만.
4. **삭제/보류** = 행 상태를 ❌/⏸로(행 자체는 남김 — 이력).
5. **변경로그 append**: index 하단에 `YYYY-MM-DD | 무엇 | 왜` 한 줄. 이것으로 이력 끝 — 본문 산문을 고치러 다니지 말 것. 시작 훅이 길이 축약을 알린 index는 현행 상태·다음 행동만 유지하고 오래된 상세 로그를 날짜별 `todo/archive/` 문서로 보존·연결한다(삭제·본문 중복 금지).
6. **inbox 훑기**: `todo/_inbox.md`에 이번 변경으로 분류 가능해진 항목 있으면 이동.
7. **파급 확인 1회**: 이 변경이 다른 문서의 "현재=" 줄이나 포인터를 낡게 만들었나 — 만들었으면 그 포인터만 갱신(내용 복제 금지).
8. **보고**: 바뀐 행 / 로그 줄 — 2줄.
