공용 메모리와 작업 인계를 함께 갱신하라. `philip:memory` 한 번으로 아래 인계 절차와 기존 장기 메모리 절차를 모두 수행한다. 장기 메모리 후보가 없어도 인계 점검은 생략하지 않는다.

## 작업 인계 (매번 먼저)

1. **실제 원본 확인** — 현재 프로젝트·작업 폴더·브랜치와 변경 파일, 루트 `MEMORY.md`, `.psp/runtime.json`의 `memory_dirs`, 현행 todo index를 읽는다. 상대 경로는 프로젝트 기준으로 해석한다. 기존 메모리는 그 원본을 갱신하고 복사본을 만들지 않는다. 연결이 없으면 프로젝트 `memory/MEMORY.md`를 만들고 루트 인덱스에서 연결한다. 다른 프로젝트·워크트리의 기록은 섞지 않는다.
2. **인계 점검표 갱신** — 현행 `todo/<작업>/index.md`에 `작업 인계` 표를 만들거나 같은 표를 갱신한다. 기존 상태 행은 원래 위치에서 수정하고 인계 표에서는 링크로 참조한다. 현행 작업이 없으면 `todo/index.md`를 쓴다. 아래 항목을 모두 점검해 `확인됨 / 해당 없음 / 미확인 / 이전 불가`와 근거를 적는다. 모르는 것을 빈칸·정상으로 처리하지 않는다. 확인 시각·시간대와 작업 폴더를 남긴다.

   | 항목 | 남길 내용 |
   |---|---|
   | 대화 맥락 | 사용자 목표·최근 정정·합의한 범위·제약·미답변 질문. 관찰 사실과 가설을 구분하고 결정 이유를 짧게 기록한다. 대화 전문이나 비공개 내부 추론을 복제하지 않는다. |
   | 작업·변경 파일 | 현재 상태 행 링크, 브랜치·HEAD(있는 경우), 수정·신규 파일과 목적, 미커밋 변경, 다른 작업자의 변경 여부. git 없는 폴더는 실제 파일 근거로 기록한다. |
   | 검증·실패 | 실제 실행 명령·작업 경로·결과·로그 위치, 미검증 범위, 실패한 접근과 재시도 조건. 오래된 검증을 현재 코드의 성공으로 쓰지 않는다. |
   | 재개 지점 | 다음 행동 1개와 완료 판단 기준, 막힌 이유·필요한 입력. 완료된 작업에는 남은 작업 없음을 명시한다. |
   | 실행 중인 작업 | 이 작업과 관련된 서버·학습·백그라운드 명령의 확인 가능한 PID/작업 ID·로그·출력 위치·관찰 시각. 기록만 있으면 실행 여부 미확인. 자동 종료·재시작하지 않는다. |
   | 세션 | 현재 도구와 확인 가능한 재개 식별자·기록 위치. 세션 자체는 도구 간 이전 불가이며 다음 도구는 이 표와 파일을 읽어 재개한다. 없는 ID는 만들지 않는다. |
   | 규칙 | AGENTS.md·CLAUDE.md·상위/하위 지침의 적용 범위와 의미상 차이. 공용으로 합의된 결정은 기존 원본에 반영하고 반대쪽은 지원되는 참조로 연결한다. 기존 본문을 통째로 덮지 않는다. 충돌하는 규칙은 임의 선택하지 않고 차이와 필요한 결정을 기록한다. |
   | 능력·환경 | 작업에 필요한 MCP·스킬·플러그인·훅·CLI·런타임의 이름, 확인한 버전/경로·로딩 또는 실행 결과, 상대 도구의 사용 가능 여부와 설정 방법. 미설치를 설치 완료로 쓰지 않는다. 전체 사용자 폴더나 무관한 프로젝트를 매번 조사하지 않는다. |
   | 권한·인증 | 사용자 승인 범위와 보류 사항, 도구별 별도 승인·로그인 필요 여부. 토큰·쿠키·키·환경변수 비밀값·인증 DB는 저장/복사하지 않는다. 우회 설정이나 과거 승인을 상대 도구 권한으로 변환하지 않는다. |
   | 공유·동시 작업 | 공용 메모리 경로, 외부 경로 접근 가능 여부, 다른 머신에서 필요한 경로 연결, 동시 편집 중인 파일과 충돌 여부. 다른 도구의 실제 읽기/실행을 확인하지 않았다면 인계 완료와 구분해 미검증으로 적는다. |

3. **회수 경로 연결** — 루트 `MEMORY.md`와 실제 공용 메모리 인덱스에서 위 todo index로 연결되는 기존 링크를 재사용하거나 한 줄 추가한다. 트리거는 "도구 전환·새 세션·이어서 작업하기 전에"를 포함한다. 상태 본문은 메모리에 중복하지 않는다. 클로드 자동 메모리 위치가 별도로 설정되어 있으면 그 인덱스에서도 같은 원본에 도달하는지 확인한다. 연결을 위해 인증/권한 설정이나 기존 자동 메모리 경로를 임의 변경하지 않는다.
4. **시작 훅 연결·재확인** — `.psp/runtime.json`의 기존 키를 보존하고 `handoff_index`에 이번 todo index의 프로젝트 기준 상대 경로를 기록한다. 없으면 객체를 생성한다. roadmap에 `현재 = <ID>`가 있고 대응하는 `todo/<ID>*/index.md`가 있으면 시작 훅은 그 현재 인계를 우선하고 `handoff_index`는 fallback으로 쓴다. 여러 제품 인계를 전부 주입하지 말고 roadmap 현재 포인터 하나를 갱신한다. 긴 인계는 현재·다음·상단·링크 일부만 최종 바이트 상한 안에서 들어가므로 index에는 현행 상태와 재개 지점을 앞세우고 상세 이력은 연결 문서로 둔다. 상태 본문은 JSON에 복사하지 않는다. 변경한 표·메모리 본문·인덱스를 다시 읽고 링크 대상 존재와 변경 diff를 확인한다. 기록 이후 코드가 바뀌면 관련 검증의 유효성을 다시 표시한다. 쓰기 직전 다른 작업자가 수정했으면 다시 읽고 병합하며 덮어쓰지 않는다. 저장 성공과 상대 도구의 회수 성공은 별도로 보고한다.

## 장기 메모리

1. **저장 판정** — 후보가 다음 중 하나인가: 사용자 선호·교정(왜 포함) / 확정 결정+근거 / 외부·실측 팩트 / 다음 세션에도 유효한 프로젝트 맥락. **탈락**: 코드 구조·경로(코드가 진실) / 이번 대화 한정 / 진행 상태(todo가 SSOT) / 사용자 감정·반응 묘사 / repo 문서에 이미 있는 것(포인터만).
2. **중복 확인** — 기존 파일이 이미 다루면 새 파일 금지, 그 파일을 갱신. 코드와 충돌하는 낡은 메모리를 발견하면 그 자리에서 수정/삭제.
3. **규격** — 파일명 `타입_슬러그.md`(user/feedback/project/reference), frontmatter(name·description·type), 본문 ≤60줄(넘으면 repo 문서로 이관+포인터). feedback은 **Why / How to apply** 필수.
4. **인덱스 동기(같은 턴 의무)** — MEMORY.md에 한 줄: `- [제목](파일.md) — 요지. "…물을 때/…전에" 회수 트리거.` 트리거 구문 없으면 다시 써라. 삭제·개명도 인덱스 즉시 반영. 인덱스 50줄 초과 시 청소 먼저.
5. **링크 무결성 점검** — 저장/개명/삭제로 `[[링크]]`를 건드렸으면 `python "${CLAUDE_PLUGIN_ROOT}/tools/mem_graph.py" <메모리폴더>` 실행: 끊긴 링크(오타·미작성)·고아 노드를 확인해 그 자리에서 교정. 시각 감사가 필요하면 메모리 폴더를 Obsidian 볼트로 열어 그래프로 본다(설정=`templates/obsidian/`, 위키링크·자동프로퍼티오염 방지). 규격·설정은 [05](docs/05_obsidian.md).
6. **원격 메모리 이식** — 아래로 url·slug를 해결한다. 설정 존재만으로 외부 전송 승인을 추정하지 않는다. 기존 승인 범위가 해당 저장소와 자료를 포함할 때 push하고, 아니면 로컬 저장을 마친 뒤 전송 보류를 보고한다. todo 인계 기록은 이 메모리 push에 포함되지 않으며 다른 머신 전달에는 별도 프로젝트 동기화가 필요하다.
   - **url** = `.claude/psp.config.json`의 `memory.url` **있으면 그것**, 없으면 머신 기본 `~/.claude/memory_repo.txt`(한 줄=레포 URL). **둘 다 없으면 이식 미설정 → 생략**(그 머신은 이식 안 쓰는 것).
   - **slug** = `memory.slug` 있으면 그것, 없으면 **프로젝트 루트 폴더명**(예: `my_project`).
   - **여러 폴더** = `.psp/runtime.json`의 `memory_collections` 객체로 폴더별 고정 이름을 관리한다(예: `{"legacy":"기존 폴더 경로","project":"memory"}`). 처음에는 실제 경로·기존 원격 배치를 확인하고 연결한다. 폴더 순서나 머신 절대경로 해시로 이름을 만들지 않는다. 같은 이름에 두 폴더를 연결하지 않는다. 기존 단일 폴더의 slug 루트 배치는 유지하고 추가 폴더에는 `--collection <고정이름>`을 사용한다. 신규 프로젝트는 폴더마다 이름을 부여한다. 모호하면 로컬 저장을 완료하고 원격 전송만 보류한다.
   - 이름 있는 묶음은 `레포/.psp-collections/<slug>/<collection>/`에 저장한다. 기존 단일 원본 `레포/<slug>/`와 분리하므로 재귀 복원 때 다른 묶음이 섞이지 않는다. 이전 형식 `레포/<slug>/<collection>/`이 있으면 도구는 중단한다. 해당 경로가 실제 메모리 묶음인지 확인하고 백업·내용 대조 후 별도 이관하며, 원본은 확인 없이 삭제하지 않는다.
   - 각 폴더마다 아래 명령에서 `--gitpush`를 빼고 먼저 계획을 확인한다. 신규 폴더는 `--collection`을 포함한다. 적용할 때 같은 인자에 `--apply`와 승인된 경우에만 `--gitpush`를 붙인다. 기본 실행은 계획만 출력하며 삭제는 전파하지 않는다. 변경 파일은 덮어쓰기 전 백업한다. 기록 삭제가 필요하면 별도 백업·대상 확인 절차로 처리한다. 인계 todo는 프로젝트 원본을 별도 동기화해야 한다.
   - 계획: 단일 메모리 폴더 프로젝트는 프로젝트 루트에서 `python "${CLAUDE_PLUGIN_ROOT}/tools/mem_sync.py" push`만 실행해 config/machine 기본 URL, config/폴더명 slug, runtime의 단일 memory_dirs를 자동 해석한다. 여러 폴더나 다른 루트에서 실행할 때만 `--project`·`--memdir`·`--collection`을 명시한다. 기존 루트 배치의 원본 폴더만 collection을 생략한다. 레포 기본 경로는 `<USERPROFILE>/.claude/claude-memory`이며 셸이 편 `~`를 넘기지 않는다. 로컬 클론이 없으면 계획은 중단되므로 승인된 clone 후 다시 비교한다. 확인한 계획을 적용하려면 `--apply`, 원격 전송까지 승인되었으면 `--gitpush`도 추가한다. 원본 메모리는 읽기만 한다. `runtime.json`의 `memory_dirs`가 여러 개면 도구는 폴더를 추측하지 않고 멈춘다 — `--memdir`(추가 폴더면 `--collection`)를 명시한다. `MEMORY.md`를 덮어써 대상에 남는 메모리가 인덱스에서 빠지는 계획도 멈추며, 의도한 경우에만 `--allow-index-drop`을 붙인다.
   - 머신 기본 URL은 모든 프로젝트에서 재사용한다. 전송할 자료의 승인 범위와 민감정보 포함 여부는 별도 확인한다. 규격 [05](docs/05_obsidian.md).
7. **보고** — 공용 메모리 변경·인계 표 링크·링크 검사·원격 push 여부, 미확인/이전 불가 항목과 필요한 다음 행동을 짧게 보고한다. 장기 저장 후보가 없으면 그 이유를 적되 인계 표 점검 결과는 반드시 남긴다. 상대 도구를 직접 실행해 회수까지 검증하지 않았다면 "양쪽 인계 실측 완료"라고 말하지 않는다.

⚠ 같은 지시가 반복돼 feedback을 적으려는 경우: 먼저 "이건 커맨드/훅으로 만들 문제인가?"를 사용자에게 제안하라(절차 불이행은 구조로 푼다 — philip-relay/01).
