---
description: (CV·DL 전용) 실험 결과 판정 — 실패를 단정하지 않고 원인을 4분해. 인자 = 실험/run
---
$ARGUMENTS 실험을 판정하라. **"안 됐다 = 방향이 틀렸다"는 금지된 추론이다** — 아래 순서로 원인을 귀속시킨 뒤에만 판정을 말한다.

1. **증거 수집(판정 전 필수)**: loss/metric **곡선**(최종 수치 하나 금지)·설정 파일·데이터 버전·로그의 경고. 곡선이 없으면 판정 불가 — 곡선 저장부터.
2. **원인 4분해** (위에서부터 소거 — 순서 중요, 흔한 원인이 먼저):
   - **(a) 구현 버그인가**: 스모크 테스트 — 작은 배치 하나에 과적합되나? 안 되면 학습 루프·손실·라벨 정렬 버그부터 의심(방향 논할 자격 없음).
   - **(b) 수치·스케일인가**: 곡선 모양 판독 — 발산(lr↓)·미수렴(lr↑/스텝↑)·과적합(정규화/데이터↑). **한 변수만** 바꾼 재실험 1~2회로 확인. lr·배치·워밍업이 그저 안 맞았을 뿐일 가능성을 먼저 소거.
   - **(c) 데이터·전처리인가**: 입력 실물 몇 개를 눈으로(증강 깨짐·라벨 오류·정규화 통계 누수·train/val 오염).
   - **(d) 방향 자체인가**: (a)~(c)가 소거되고, **합리적 수치 범위 스윕에서도** 베이스라인을 못 넘을 때만 도달 가능한 결론.
3. **판정 어휘 고정**: `버그 수정 필요 / 수치 재탐색(범위 제시) / 데이터 문제 / 방향 기각(스윕 근거 첨부) / 판정 불가(부족한 증거 명시)` — 이 다섯 중 하나로만.
4. **기록**: run 디렉터리에 판정·근거 한 줄 append(다음에 같은 걸 다시 안 돌리게).

**보고**: 곡선 관찰 → 소거 과정 → 판정(어휘 고정) → 다음 실험 1개 제안(한 변수).
