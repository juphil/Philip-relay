현재 질문과 관련된 기준선·결정·변경·검증을 읽고 브리핑한다. 전체 대화나 저장소를 무조건 전수 회수하지 않는다. 이미 폐기되거나 해결된 방식을 현재 문제로 되살리지 않는다.

## 기본 구성

1. **한 줄 결론**: 지금 내려야 할 판단과 가장 큰 근거.
2. **확인 범위**: 본 파일·실행·데이터·환경과 보지 못한 범위.
3. **현재 기준선**: 실제 적용·배포·운영 중인 상태. 제안·실험·구현·배포를 구분한다.
4. **해결된 문제**: 문제, 변경, 검증 근거. 단순 기동은 효과 검증으로 쓰지 않는다.
5. **미해결 문제**: 현상, 확인된 원인 또는 가설, 현재 방어책, 한계, 필요한 검증.
6. **전후 비교**: 비교 가능한 조건과 지표가 있을 때만 표로 제시한다. 측정과 예측, 오프라인과 실제 운영을 섞지 않는다.
7. **다음 결정**: 지금 실행 가능한 한 단계, 채택 기준, 중단 조건.

작업 성격상 파이프라인·실험표·준비도 표가 필요할 때만 추가한다. 지표는 사용자 영향과 실패 유형을 분리할 수 있게 고른다. 하나의 종합 점수로 서로 다른 실패를 숨기지 않는다. CV·DL 수치 전수보존은 `/philip:exp`, 실패 원인 판정은 `/philip:judge`를 함께 쓴다.

코드·설정 변경은 브리핑 요청 자체로 승인된 것이 아니다. 수정이 요청되면 현재 상태, 변경안, 예상 영향, 검증 방법을 연결해 실행한다.
