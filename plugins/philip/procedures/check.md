---
description: 정밀검토 — 인자 '현작업'(기본) 또는 '전체'
---
$ARGUMENTS 범위로 정밀검토하라. 고치라는 지시가 아니다 — **발견·보고까지**(수정은 사용자 허락 후).

**현작업** (기본): 이번 세션에서 만진 파일들만.
- **단정 검사(최우선)**: 이번 작업에서 내가 한 주장 중 **실물(파일·실행)을 안 열고 쓴 것**이 있는가 — 있으면 지금 열어 확인하고, 틀렸으면 정정을 명시 보고.
- 코드: 수명주기 순서 / null·경계값(종이 시뮬레이션으로 극단 입력 대입) / 이벤트·코루틴 정리 짝 / 루프 내 할당·Find / 하드코딩 수치.
- 문서: 방금 고친 곳 **주변 전문 재독** — 수술적 편집이 남긴 낡은 주장·모순(다른 절의 요약·상태 표기가 새 내용과 충돌하는지).

**전체**: 위에 더해 —
- 상태 드리프트: roadmap "현재=" ↔ 현행 index 표 ↔ 실제 최근 작업이 일치하나.
- SSOT 위반: 같은 사실이 두 문서에 서술돼 있나(한쪽 포인터화 후보 목록).
- 죽은 참조: 깨진 링크·인덱스에 없는 메모리·존재하지 않는 파일 포인터.
- 침묵 결함 grep: 문서가 언급하는 식별자(신호명·키·함수)가 코드에 실재하는지 1회 교차(문서만 있는 유령 식별자 = 미배선 후보).

**보고 양식**: 심각순 목록 — `[심각도] 파일:줄 — 무엇 — 왜 문제 — 제안` / 이상 없으면 "통과, 확인 범위 명시".
