description: 웹/UI 디자인 감사 — 실제 렌더·상태·치수·접근성을 점검해 발견과 근거만 보고한다
---
화면/UI를 감사하라. **이 스킬은 발견·보고만 하며 파일을 수정하지 않는다.** 수정까지 승인됐으면 `/philip:designfix`를 사용한다. 브라우저 또는 실제 렌더 실측 기준이며 코드만 보고 통과하지 않는다.

0. **레퍼런스 모드**: `복제 목표 / 제약 / 영감 / 안티패턴` 중 어떤 모드인지 확인한다. 복제 목표일 때만 실물 소스의 구조·값을 그대로 대조한다. 영감은 목적과 원리를, 제약은 지정 항목만, 안티패턴은 피할 요소만 평가한다. 모드가 불명확하면 감사 결과에 불확실성으로 남긴다.

1. **뻔함 검사**: 프레임워크 기본값 그대로인가 — 기본 폰트 스택·기본 버튼·보라/파랑 그라데이션·중앙 카드 한 장·균등 3열 카드 그리드 같은 "AI/템플릿 냄새" 요소를 지목. 각 주요 선택(레이아웃·타이포 스케일·색·여백 리듬)에 **근거 한 줄**이 있는가 — 없으면 그건 선택이 아니라 디폴트다 → 대안 제시.
2. **치수 실측**: 프로젝트 스펙의 간격·브레이크포인트·최대폭·토큰과 실제 렌더를 대조한다. 대표 뷰포트는 제품 지원 범위에서 고른다. 고정된 3종을 모든 프로젝트에 강제하지 않는다.
2.5 **공통 품질**: [웹/UI 공통 매뉴얼](../docs/06_web_ui_manual.md)의 정보 우선순위, 정렬·리듬, 상태 안정성, 반응형, 접근성, 시각 QA를 확인한다. 제품별 숫자는 프로젝트 UI 프로필에 있을 때만 사용한다.
2.6 **실측 방법**: `getBoundingClientRect`·`getComputedStyle`과 캡처를 위험에 맞게 사용한다. 정상·빈 데이터·로딩·오류·긴 문자열 상태를 비교하고 측정 도구의 한계를 기록한다. 사용자의 실행본을 임의로 종료하지 않는다.
3. **비정상 상태 3종**: 빈 데이터 / 로딩 / 에러 상태가 설계돼 있는가(해피패스만 = 미완). **실데이터 극단값**(아주 긴 이름·긴 문자열·0개·1000개)으로 레이아웃이 버티는지.
4. **상호작용 최소선**: 포커스 표시·hover/active 구분·키보드 도달·의미 구조·대비를 대상 표준과 프로젝트 기준에 맞춰 확인한다.
5. **의존성 검사**: 이번에 추가한 라이브러리가 기존 스택으로 대체 가능했는가 — 가능했으면 제거 제안.

**보고**: `[심각도] 화면/상태 — 관찰 — 근거 — 영향 — 수정 제안` 형식. 수정하지 않았음을 명시하고, 보지 않은 뷰포트·상태·브라우저를 통과로 쓰지 않는다.
