---
description: 프로젝트 상태 파악 — 기준선에서 현재 질문에 필요한 변경·메모리·미완료 근거를 점진적으로 회수한다
---
프로젝트의 현재 상태를 질문에 충분한 깊이까지 파악하라. 모든 메모리와 한 달치 기록을 무조건 컨텍스트에 넣지 않는다. 새 질문이나 외부 상태 변화가 생기면 필요한 근거를 다시 찾는 것이 정상이다. 실물을 연 근거로만 말한다.

1. **기준선**: 프로젝트 진입 규칙, `MEMORY.md`, `.psp/runtime.json`, todo/roadmap의 현재 포인터와 현행 index를 연다. 표만으로 완료나 다음 작업을 단정하지 않는다.

2. **관련 변화**: 현재 질문·작업·열린 항목과 관련된 최근 커밋과 로그부터 본다. 날짜 범위는 고정하지 않는다. 원인이나 드리프트가 불명확할 때만 범위를 넓힌다.

3. **선택 회수**: 인덱스의 회수 트리거로 관련 메모리 본문을 연다. 상시 안전·불가침 결정은 작업과 관련되면 반드시 읽고, 무관한 토픽은 읽지 않는다. 인덱스 한 줄을 본문 확인으로 대신하지 않는다.

4. **닫힘 여부 판정**: 최근 작업들이 검증·실측까지 끝나 **닫혔는가**, 아니면 "코드만 반영·미검증·미실측"으로 매달려 있는가. 열려 있는 최근 작업 = 진짜 다음 할 일 1순위(외부 대기 없이 지금 손댈 수 있는 것).

5. **드리프트 교차**: roadmap 현재 포인터, index, 관련 최근 작업, 회수한 메모리가 일치하는지 본다. 표 밖 트랙이 현재 질문에 영향을 주면 명시한다. 전체 저장소 감사가 필요할 때만 `/philip:check 전체`로 확장한다.

6. **브리핑**: 트랙별로 (진짜 마지막 상태 + 닫혔나 여부) + **지금 당장 실측 가능한 것 vs 외부 대기**를 구분 → 추천 다음 작업 1개 + 근거. 옵션 나열 금지.

**금지**: 관련 변경기록·메모리 본문을 안 열고 로드맵이나 기억만으로 파악했다고 하는 것. 확인 범위를 전체 프로젝트 지식으로 과장하지 않는다.
