# 웹/UI 공통 행동매뉴얼

이 문서는 제품과 무관하게 재사용할 작업 방식만 정의한다. 특정 제품에서 확정한 숫자와 화면 구성은 해당 프로젝트 프로필이나 별도 지식 저장소에 두며, 다른 프로젝트에 자동 적용하지 않는다.

## 1. 시작 전에

- 사용자, 핵심 과업, 지원 뷰포트·브라우저, 정보 우선순위, 정상·빈 데이터·로딩·오류 상태를 확인한다.
- 기존 디자인 시스템과 프로젝트 UI 프로필을 먼저 연다. 없으면 타이포·색·간격·반경·컨트롤 크기의 최소 토큰을 정하고 근거를 남긴다.
- 레퍼런스는 `복제 목표 / 제약 / 영감 / 안티패턴` 중 하나로 분류한다. 복제 목표일 때만 구조와 값을 그대로 옮긴다.
- 큰 정보 구조·배치·UX 흐름은 구현 전에 사용자와 합의한다. 세부 구현 승인으로 제품 방향 변경까지 허가받은 것은 아니다.

## 2. 정보와 문구

- 화면에는 사용자가 현재 판단하고 행동하는 데 필요한 정보만 둔다. 도움말·온보딩·고급 진단이 필요한 제품에서는 설명을 금지하지 말고 적절한 계층에 둔다.
- 오류는 사용자에게 이해 가능한 상태와 복구 행동을 제공한다. 기술 코드·경로·비밀·관리자용 세부는 진단 영역으로 분리한다.
- 버튼과 라벨은 과업을 명확히 드러내며, 약어·괄호·내부 용어는 대상 사용자가 실제로 이해할 때만 쓴다.
- 색만으로 성공·실패·선택을 전달하지 않는다. 텍스트·아이콘·의미 구조를 함께 쓴다.

## 3. 레이아웃과 상태

- 같은 계층과 같은 종류의 컨트롤은 토큰·정렬·동작을 일관되게 유지한다.
- 반복되는 간격과 세로 리듬은 프로젝트 토큰으로 측정한다. Philip Relay가 특정 px 값을 전역 기본으로 강제하지 않는다.
- 콘텐츠 길이와 상태 변화가 이웃 영역을 예측 불가능하게 밀지 않도록 안정적인 영역, 줄바꿈, 스크롤, 축약 정책을 설계한다. 고정 높이가 항상 정답은 아니다.
- 이미지·영상은 제품 요구에 맞는 aspect ratio와 fit 정책을 정의한다. 빈 상태도 깨진 이미지나 누락된 컨트롤처럼 보이지 않게 한다.
- 반응형은 모바일·태블릿·데스크톱이라는 이름보다 실제 지원 폭과 과업 변화로 브레이크포인트를 정한다.
- 초기 렌더와 hydration·비동기 갱신 사이에서 의미·색·레이아웃이 불필요하게 튀지 않게 한다.

## 4. 접근성과 상호작용

- 키보드 도달, 보이는 포커스, 의미 있는 label/name, 논리적 읽기 순서, 충분한 터치 영역을 확인한다.
- hover만으로 정보를 숨기지 않고 reduced motion, 확대, 고대비·색각 차이를 고려한다.
- 대비 기준은 대상 표준과 글자 크기·역할에 맞춰 측정한다. WCAG 수치를 무맥락으로 한 값에 고정하지 않는다.
- 정상 경로뿐 아니라 취소·재시도·중복 제출·느린 응답·권한 거부·연결 끊김을 설계한다.

## 5. 검증

- 실제 렌더를 열어 대표 뷰포트와 정상·빈 데이터·로딩·오류·극단 길이 상태를 본다.
- 치수·계산 스타일·대비·포커스 순서가 중요하면 브라우저 측정값으로 남긴다. 캡처와 숫자 중 하나만으로 다른 쪽을 대신하지 않는다.
- 헤드리스·가상 시간·모의 장치의 한계를 기록한다. 못 본 브라우저·실장치·상태를 통과로 쓰지 않는다.
- 감사와 수정은 분리한다. `/philip:designcheck`는 발견만, 승인된 `/philip:designfix`는 수정과 재측정을 수행한다.
- 배포 동일성을 주장하려면 실제 배포 산출물의 버전·해시·동작을 확인한다.

## 6. 프로젝트 프로필

제품별 프로필에는 토큰, 브레이크포인트, 화면 구분, 확정 UX, 허용 예외, 검토 일자를 둔다. 프로필 값은 공통 매뉴얼에 복사하지 않는다. 다른 프로젝트에 재사용하려면 적용 조건과 반례를 다시 검토한다.

제품별 치수, 화면 개수, 미디어 비율, 사용자 역할별 화면 구성은 프로젝트 소유 정보다. 공통 매뉴얼로 승격하려면 여러 제품에서의 적용 조건과 반례를 다시 검토한다.
