# 08 삭제·덮어쓰기 표준 (실수 방지 공통 기본값 — 모든 프로젝트·클로드·코덱스 공통)

> 한 줄: **기본은 지우기 전에 목록을 보고 되돌릴 수 있게 옮긴다. 정확한 대상을 사용자가 명시 승인하면 영구 삭제도 실행할 수 있다.**

## 1. 왜 최우선인가 (검증된 실패 사례)
- 고아 브랜치를 만들면서 **작업 트리에서** `git checkout --orphan` → `git rm -rfq --cached .` → `git clean -fdxq` 를 실행한 사례가 있었다.
  `-x` 때문에 `.gitignore` 대상(모델·엔진·`.env` 류·실행 결과·학습 산출물·실험 원자료·백업 폴더)까지 저장소 전체에서 영구 삭제.
  셸 삭제는 휴지통을 거치지 않아 휴지통 0건. 하루 뒤 GPU 검증이 모델을 못 찾아서야 발견.
- 복구: USB·학습 서버·깃 이력·봉인 납품본에서 사본 있는 것만 되살림. 실행 로그·결과·실험 원자료·백업 폴더 수 GB 는 영구 손실.
- 교훈: 깃은 **추적 파일만** 지켜 준다. 깃 밖 자산(모델·데이터·결과·비밀 설정)은 한 번 지우면 끝이다.

## 2. 적용 범위 — 아래는 전부 "삭제·덮어쓰기"로 취급한다
| 분류 | 예 |
|---|---|
| 파일·폴더 삭제 | `rm`, `rmdir`, `del`, `rd`, `Remove-Item`, `shutil.rmtree`, `os.remove`, `Path.unlink`, `fs.rmSync`, `find -delete`·`find -exec rm`, `rsync --delete`·`--remove-source-files`, `truncate` |
| git 작업 트리 소실 | `git clean`(특히 `-x`), `git reset --hard`, `git checkout -- <경로>`, `git checkout -f`, `git restore <경로>`, `git stash drop/clear`, `git branch -D` |
| 브랜치 생성·전환으로 생기는 소실 | 작업 트리에서 `--orphan` 생성 후 비우기, 추적 밖 파일과 이름이 겹치는 브랜치로 전환 |
| 덮어쓰기 | 기존 파일 위로 `cp`/`mv`/`Copy-Item -Force`, 리다이렉션 `>`, 압축 해제 덮어쓰기, 동기화 도구 미러(`robocopy /MIR`, `rsync --delete`) |
| 데이터 | DB `DELETE`/`DROP`/`TRUNCATE`, 결과 테이블 정정 |
| 원격 | `git push --force`, 원격 브랜치·릴리스·아티팩트 삭제, 클라우드 객체 삭제 |

## 3. 기본 절차와 사용자 승인 예외
1. **미리보기** — 실행 전에 대상 목록을 뽑는다.
   - 파일: `python <philip-plugin>/tools/safe_delete.py <경로...>` (옮길 대상·파일 수·크기·이동처 출력, 실행 안 함)
   - git: `git clean -n -d [-x]`, `git status --porcelain --ignored` (**깃 제외 파일이 섞였는지 반드시 확인**)
   - 덮어쓰기: 대상 경로에 이미 있는 파일 목록, 원본·대상 크기·수정 시각 비교
   - DB: 같은 조건의 `SELECT COUNT(*)` 와 표본 행
2. **재검토** — 목록을 다시 읽고 의도 밖 항목이 0인지 확인한다. 다음 중 하나라도 해당하면 **사용자에게 목록을 보여 주고 승인**을 받는다.
   - 깃 밖 파일(무시·미추적)이 포함됨 · 대상 100개 초과 또는 100MB 초과 · 모델·데이터셋·결과·비밀 설정·백업·`*_KEEP` 포함 · 다른 PC·서버·원격
3. **기본은 되돌릴 수 있는 방식으로 실행**
   - 파일·폴더: `safe_delete.py <경로...> --yes` → 휴지통(고정 디스크·1GB 이하) 또는 `<프로젝트>/_quarantine/<YYYYMMDD_HHMMSS>/<원래 경로>` 격리 + `manifest.tsv`(원래 경로·크기·SHA-256)
   - git 정리·고아 브랜치: **작업 트리에서 하지 않는다.** `git clone <원격> %TEMP%\x` 또는 `git worktree add` 에서 하고, 결과만 푸시
   - 덮어쓰기: 덮기 전 원본을 격리 폴더로 복사(또는 `.bak_<시각>`), 그 뒤 쓰기
   - DB: 대상 행을 백업 테이블·파일로 먼저 저장(행 삭제 금지 규칙이 있는 프로젝트는 UPDATE 로만)
   - 사용자가 미리보기의 **정확한 경로를 영구 삭제하도록 현재 대화에서 명시 승인**했다면
     `safe_delete.py <경로...> --permanent --confirmed-by-user --yes`로 실행할 수 있다. 이는 일반 삭제 명령 우회가 아니라 승인 범위를 명령에 명시하는 경로다.
   - 드라이브 루트·사용자 홈·현재 프로젝트 루트처럼 범위가 지나치게 넓은 대상은 이 도구로 영구 삭제하지 않는다. 더 좁은 하위 대상을 다시 지정한다.
4. **사후 확인·보고** — 무엇을 어디로 옮겼는지(개수·크기·격리 세션 이름)와 복원 방법을 보고한다.
5. **비우기** — 격리 폴더는 보존 기간(기본 30일) 지나고 사용자가 확인한 뒤에만 `safe_delete.py --purge-older-than 30 --yes`. 휴지통 비우기는 사용자가 한다.

## 4. 금지
- 작업 트리에서 `git clean -x` (예외 없음). `git clean` 자체도 `-n` 미리보기 없이 실행 금지.
- 대상이 변수(`$S`, `%X%`)뿐이라 실제 경로가 보이지 않는 삭제 명령 — 경로를 풀어 쓴 미리보기를 먼저.
- 이동식 디스크(USB)·1GB 초과 항목을 휴지통으로 보내기 — 휴지통이 없거나 넘쳐 **묻지 않고 영구 삭제**된다(safe_delete 가 자동으로 격리 폴더로 돌린다).
- 훅 차단을 다른 명령으로 우회하기(예: 스크립트 파일에 삭제를 넣어 실행). 영구 삭제가 필요하면 일반 삭제 명령으로 우회하지 않고 위 승인 경로를 사용한다.

## 5. 강제 장치 (Philip Relay 플러그인)
| 장치 | 동작 |
|---|---|
| `hooks/agent_hook.py deleteguard` (PreToolUse: Bash·PowerShell·셸) | 흔한 실수 명령을 한 번 멈추고 이 절차를 안내. 허용 = 미리보기(`git clean -n`, `-WhatIf`), 대상이 전부 임시 폴더인 삭제, 승인 절차를 내장한 `safe_delete.py`, 안전형 `git push --force-with-lease` |
| `tools/safe_delete.py` | 기본 미리보기→`--yes` 휴지통/격리. 사용자 승인 영구 삭제=`--permanent --confirmed-by-user --yes`. 광범위 루트는 거부. `--list`·`--restore`·30일 이후 purge 지원 |
| SessionStart·사건 기반 포인터 | 세션 시작에 안전 규칙을 넣고, 규칙 변경·변경 시작·검토·완료 주장 같은 사건에 관련 포인터만 넣는다 |
| 편집 가드 | `_quarantine/*` 직접 편집 차단(격리본 보존) |

한계(훅이 못 막는 것 — 3절 절차가 1차 방어선):
- 이 훅은 악의적인 명령을 완전히 봉쇄하는 보안 샌드박스가 아니라 실수 방지 장치다. 모든 셸 문법과 중첩 래퍼를 추적하려고 정상 명령까지 과잉 차단하지 않는다.
- 스크립트 파일 안의 삭제(`python 정리.py`), 원격 서버 셸(`ssh … rm`)의 원격 측 삭제.
- `find -exec sh -c 'rm …'`, 전역 옵션이 시작 경로보다 앞서는 `find`, 옵션이 위치 인자 뒤에 오는 일부 `rsync` 형태는 정밀 경로 판정이 불완전할 수 있다.
- **덮어쓰기**: `cp`·`mv`·`Copy-Item -Force`·리다이렉션 `>`·압축 해제·`robocopy /MIR` 는 대상에 무엇이 있었는지 훅이 알 수 없어 차단하지 않는다 → 덮기 전 대상 목록 확인·원본 격리 복사를 절차로 지킨다.
- `git push --force-with-lease` 는 원격이 예상 상태일 때만 덮는 안전형이라 훅은 허용한다(그래도 실행 전 사용자 확인과 예상 SHA 고정 필요). 일반 `--force`·`-f`는 계속 차단한다.
- 훅 자체가 오류로 죽으면 셸 명령을 막지 않는다(전체 셸 마비 방지 — 편집 가드는 반대로 막는다).
- 격리 복원: 세션 이름(프로젝트 `_quarantine`) 또는 세션 폴더 절대경로(드라이브 `_psp_quarantine`)로 `--restore`. 이미 파일이 있는 자리는 덮지 않고 건너뛴다.

## 6. 깃 밖 자산 백업 (프로젝트별 권장)
- 모델·엔진·데이터셋·실행 결과·실험 원자료·비밀 설정은 깃에 없으므로 **별도 사본 1곳 이상**(외장 디스크·학습 서버·NAS)과 해시 목록을 둔다(3-2-1: 사본 3·매체 2·외부 1).
- 사본 위치는 프로젝트 메모리 레퍼런스에 적어 둔다 — 사고 때 "어디서 되살리나"를 찾는 시간을 없앤다.
