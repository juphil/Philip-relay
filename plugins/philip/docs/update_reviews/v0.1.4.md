# Philip Relay v0.1.4 review

Date: 2026-10-12

## 근거 / Evidence

This release promotes only the reusable fixes independently verified in private PSP v2.11.12 and v2.11.13.

## 변경 분류 / Change classification

- Makes rapid consecutive memory-sync commits reliable by avoiding source-mtime copying and reporting both Git stdout and stderr on failure.
- Refuses approved permanent deletion of a project root, user home, drive root, or any parent directory containing those roots.
- Passes the project root selected from the working directory or `--root` through the actual deletion path, including environments without `CLAUDE_PROJECT_DIR`.
- Blocks common positional `+refspec` force-push forms while preserving the existing `--force-with-lease` exception.

## 왜곡 위험 / Distortion and public boundary

- Keeps Philip Relay branding, package names, public documentation, license, and repository metadata.
- Does not copy private release notes, profiles, project state, memory, todo data, private identifiers, or private repository policy.
- Documents that `--stdin`, inline `-c remote.<name>.push=+<refspec>`, and stored push configuration are outside the command-hook parser. The hook remains a mistake-prevention aid, not a security sandbox.

## 행동 평가 / Behavior evaluation

- Generated skills, unit tests, manifests, links, orphan and duplicate checks, current-tree privacy checks, and reachable-history privacy checks must pass before release.
- The deletion regression runs without `CLAUDE_PROJECT_DIR`, preserves a sentinel when a project parent is targeted, exercises explicit `--root`, and still permits deletion of an exact approved ordinary file.
- Windows symbolic-link coverage may be skipped when the account lacks symbolic-link privileges; all other tests must pass.
- On this Windows Codex host, all command-hook cases passed, including blocked positional `+refspec`, allowed `--force-with-lease`, protected project ancestors without `CLAUDE_PROJECT_DIR`, explicit `--root`, and exact approved-file deletion.
- Claude and Codex both consume the same hook implementation; fresh conversational sessions are not claimed by these mechanical results.

## 미검증 / Not verified here

- Fresh Claude and Codex conversational behavior evaluation remains separate from the mechanical tool and hook tests.
- Installation from the public marketplace is verified only after the public commit and tag exist.
