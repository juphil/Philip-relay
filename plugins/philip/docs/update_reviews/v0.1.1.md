# Philip Relay v0.1.1 release review

Date: 2026-10-11

## Evidence

- The first public history retained two private identifiers in an earlier checker implementation even after the current tree was cleaned.
- Destructive-operation checks missed force-with-lease pushes, path checkouts, and unquoted `cmd /c del` commands.
- Session startup could choose the newer of two divergent rule files and overwrite the other without a backup.
- Private repositories need authenticated Git metadata for update checks; unauthenticated raw URLs cannot be the source of truth.

## Changes

- Rebuilt the reachable public history from a reviewed clean tree and moved the release to `v0.1.1`.
- Promoted the reusable v2.11.1–v2.11.5 safety, update, context-budget, memory-sync, and knowledge-routing fixes.
- Made rule-file conflicts non-mutating at session start and preserved the replaced target in local application data on explicit edit synchronization.
- Split the public usage guide into English `README.md` and Korean `README.ko.md` with reciprocal links.
- Added tag freshness to the public release gate.

## Validation

- Generated-skill drift, manifests, Markdown links, orphan docs, duplicate sources, sensitive paths, secret formats, and complete reachable Git history are checked before release.
- Unit tests cover the destructive-command bypasses, rule conflict preservation, update preflight failure, authenticated remote selection, and newest-cache selection.

## Not verified

- Independent fresh Claude Code and Codex behavior sessions are not represented by these machine tests and remain a separate follow-up evaluation.
