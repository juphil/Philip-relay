# Contributing

Please include the problem, expected behavior, actual behavior, reproduction steps, host, operating system, and installed version in an issue. For a feature request, first distinguish a reusable workflow rule from a project-specific profile.

Keep each pull request focused and include:

- synchronized procedure and generated skill changes;
- scope, counterexamples, and a weaker alternative for every new hard rule;
- relevant automated tests and manual behavioral checks; and
- whether `VERSION` should change, with the reason.

Run the verification commands in README. Do not include personal paths, private repository addresses, tokens, project memory, or material with unclear ownership.

## 한국어

이슈에는 문제, 기대 행동, 실제 행동, 재현 절차, 호스트와 버전을 적어 주세요. 기능 제안은 어느 프로젝트에나 필요한 행동 규칙인지, 특정 프로젝트 프로필인지 먼저 구분해 주세요.

Pull request는 한 가지 목적에 집중하고 다음을 포함해야 합니다.

- 변경한 procedure와 생성된 skill의 동기화
- 새 강제 규칙의 적용 범위, 반례, 더 약한 대안
- 관련 자동 테스트와 수동 행동 평가 결과
- `VERSION` 변경 여부와 근거

검증 명령은 README의 개발 및 검증 절을 따릅니다. 개인 경로, 비공개 저장소 주소, 토큰, 프로젝트 메모리나 소유권이 불분명한 자료를 포함하지 마십시오.
